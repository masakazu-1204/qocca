**推奨A なら、今の広告費とほぼ同額(月¥35,100)で毎日3本が回る。**

## 16-11. ★ミーム型の作り方(2026/8/4 King指摘「オチがない」を受けて)

### 失敗から学んだこと
最初に作ったミームは**オチが無かった**。原因は2つ:
1. **映像に裏切りが無い**(おねだり→食べる→おねだり = 予想通り)
2. **テキストが最初から最後まで出っぱなし** ← オチは「後から出る」から効く

→ `add-meme-text.mjs` を **v2で時間区間指定に対応**させた(`--seg "開始,終了,位置,テキスト"`)。

### ★オチの型(これに沿って作る)

```
0〜3秒   フック    状況を提示。「え？」と思わせる
3〜5秒   タメ      期待を作る(まだテキストは前半のまま)
5〜10秒  裏切り    ★映像が変わる + テキストが切り替わる = オチ
```

**映像とテキストの両方が同時に変わること。**片方だけだと落ちない。

### 使える型(汎用・使い回せる)

| 型 | 構造 | 例 |
|---|---|---|
| **宣言→即破り** | 真剣に宣言 → 3秒後に破ってる | 「今日からダイエットします」→「3秒後」 |
| **建前→本音** | よそ行きの顔 → 素の顔 | 「しつけは完璧です」→「散歩のリードを見た瞬間」 |
| **1匹だけ違う** | 全員が同じ行動 → 1匹だけ違う | 「散歩いく人ー！」→「ラム(2歳):」 |
| **自信→失敗** | ドヤ顔 → やらかす | 「猫は犬より賢いんです」→ 段ボールに挟まる |
| **期待→現実** | 飼い主の理想 → うちの子の現実 | 「思い描いていた散歩」→「実際」 |

### 制作上のコツ(実測)
- **ミームは無音で生成する**。テキストが主役なので声は不要。
  → **生成が1分で終わる**(音声つきは3〜4分)。数を打つ形式に向く。
- ショートは**音を消して見る人が多い**。テキストが読めれば成立する。
- クリップは**5秒×2**で十分。10秒あればオチまで作れる。

## 16-12. ★固定キャラ「もち」体制 (2026/8/10 King決定)

Fluffie the Pom 型 —「1匹のキャラで世界観統一・日常のあらゆるシーンに登場」を採用。

### キャラ

**もち (Mochi)** — Qocca のイメージキャラ (`public/qocca_character.png`) を
image-to-image で実写化したクオッカ。**杏色オレンジ+クリームの毛・大きな丸い目・
ピンクの舌を出した笑顔・短く丸い耳。** リアル度は「実写映画のCG生物」レベル
(完全フォトリアルでも3Dアニメでもない中間)。

**Qoccaの葉っぱ**は記号として使う。**持つ / 頭にかぶる / 無し を状況で使い分ける。**
常時持たせると手が塞がって動きが制限されるため固定しない。葉に Qocca が浮き彫り。

### ★もちには2つの体型がある (重要)

| | 用途 | 参照 |
|---|---|---|
| **丸い版** | 日常・悪戯・ほほえましい回 | `sns-neta/quokka/sheet1_front_free.png` |
| **二足版** | ダンス・人間の動作を真似る回 | `sns-neta/quokka/mochi_canon_v2.png` |

二足版は Motion Control の出力から起こしたもので、体が伸びてキャラクター性が高い。
King評価は「こっちがいい感じ」。**人間の動きを載せるなら二足版**を使う。
同じ子の「立っている時」と「くつろいでいる時」として矛盾しない。

### 素材の所在

`sheet2_leafhat.png` / `sheet3_sleeping.png` / `sheet4_side.png` /
`mochi_canon_v2.png`(二足版の正典) / `dref1〜3.mp4`(モーション参照)

### 生成設定 (King確定)

```

5秒 × 3カット = 15秒 / 1本 52.5クレジット / 月34本(Max枠1800内)
```

**★高ビットレートと音声生成は追加費用ゼロ。**fast/720p/5秒は音声とビットレートを

### 構成の型

3カットあると「次どうなる?」で最後まで見られ、完走率が上がる。

## 16-13. ★トレンド乗っかり (Motion Control)

流行りのダンスを**もちが完コピ**する。Kling 3.0 Motion Control を使う。

### 手順

```
① King が流行りのダンス動画を送る
② UIを crop で切り落とし、15秒以下に分割(Kling上限)
③ Supabase に上げる → media_import_url → motion_control
④ stitch-video.mjs で結合
⑤ ★King が手動投稿。曲はInstagramアプリ内でトレンド音源を付ける
```

**⑤が重要** — 曲を焼き込むと音源ページに紐づかず、その曲を聴いている人の流れに
乗らない。**トレンド系は無音で納品する。**

### ★元動画の条件(ここが9割)

```
✅ 踊っている人が1人だけ   ✅ 字幕・テロップの焼き込みなし
✅ 全身が最後までフレーム内  ✅ 縦動画
```

実例: 2人+字幕ありの解説チャンネル切り抜き → **使えたのは29秒中11秒だけ**。
1人+字幕なしの元投稿 → **29秒フル使えた**。素材選びで結果が決まる。

### 実測・注意点

- **1回14クレジット**(8〜10秒)。29秒フルで42クレジット。安い。
- **★4割くらい失敗する。**失敗分は自動返金されるので、再投入前提で運用する。
- **遅い。**1回4〜5分。Seedance の3〜4倍。
- `scene_control: "video"` の方が成功しやすい(背景は元動画から)。
- **★分割して繋ぐと、区間ごとに見た目がズレる。**対処: 一番良い区間から
  正面フレームを1枚抜き、それを `image_id` にして他の区間を作り直すと収束する。

## 16-16. ★Instagram が動画を弾く条件 (2026/8/15 実地で判明)

`post-video-to-instagram` が `container_wait` で `container_error: ERROR` を返す場合、
**元動画のビットレートが高すぎる**可能性が高い。

| | ビットレート | 結果 |
|---|---:|---|
| Higgsfield の生ファイル | **10,318 kb/s** | ❌ Instagram が ERROR |
| 再エンコード後 | 1,845 kb/s | ✅ 投稿成功 |

Threads は同じファイルで**成功する**ため、Threads だけ通って Instagram だけ落ちる、
という分かりにくい形で出る。

### 対処 (実装済み)

`publish-video-asset.mjs` は**クリップが1本でも必ず再エンコードする**ようにした。
以前は「1本だけならコピーで済む」としていたが、それが事故の原因だった。

```
-c:v libx264 -crf 20 -pix_fmt yuv420p -profile:v high -level 4.0
-c:a aac -b:a 128k -ar 44100 -movflags +faststart
```

`+faststart` (moov atom を先頭に置く) も必須。複数クリップを `stitch-video.mjs` で
繋いだ場合は元から再エンコードされるため、この問題は起きない。

### 投稿の手順 (確立済み)

```
① publish-video-asset.mjs で登録 → video_id を得る
② dry_run で狙った動画が選ばれるか確認   ← プールに複数あると pick は別を拾う
③ video_id 指定で本番投稿
```

**「この動画を出したい」ときは必ず `video_id` を指定する。**`pick:true` は
未使用プールから勝手に選ぶため、意図しない動画が出る。
